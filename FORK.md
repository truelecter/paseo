# Fork: `truelecter/paseo`, branch `local`

`local` is an upstream release tag plus a few commits of our own and squashes of open upstream pull requests. Each change of our own also lives on its own branch, based on upstream `main` so it can become a pull request; `local` carries a cherry-pick of it. An upstream pull request is carried as one squash of its diff against its merge base with `main`. This file lists everything on `local` that upstream doesn't have, and when each piece can go.

## Android APK

`.github/workflows/android-tlctr-apk.yml` needs three repository secrets: `PASEO_GOOGLE_SERVICES_JSON` (the Firebase `google-services.json` for `sh.paseo.tlctr`, base64), `PASEO_ANDROID_KEYSTORE` (the release keystore, base64, key alias `paseo`), and `PASEO_ANDROID_KEYSTORE_PASSWORD`. The Expo project `@trlctr/paseo` holds the FCM V1 service account key for `sh.paseo.tlctr`; the daemon sends pushes through Expo with the token the app registers, so the daemon needs nothing extra. Keep the keystore: an APK signed with another key can't update the installed app.

The version comes from upstream (`packages/app/package.json`), so it moves when `local` moves to a newer tag. Each build of one version gets a build number from the workflow (`PASEO_TLCTR_BUILD`, one more than the highest `<version>-tlctr.<n>` release, at most 99): versionName `<version>-tlctr.<n>`, the same as the release tag, and versionCode `<upstream versionCode> * 100 + <n>`. The app's own version checks read `package.json`, so the suffix doesn't change them. Local builds without the variable are build 0.

To build locally: `APP_VARIANT=tlctr GOOGLE_SERVICES_FILE_TLCTR=<file> npx expo prebuild --platform android --clean` in `packages/app`, then `PASEO_ANDROID_KEYSTORE_FILE=<jks> PASEO_ANDROID_KEYSTORE_PASSWORD=<password> ./gradlew :app:assembleRelease -PreactNativeArchitectures=arm64-v8a` in `packages/app/android`. Without the keystore variables the release APK is signed with the debug key.

## Move to a newer upstream

1. Rebase `local` onto the new tag: `git rebase --onto v<new> v<old> local`. Skip a commit when upstream already has it.
2. Update "Base" and the table in this file in the same rebase (amend the `docs(fork)` commit).
3. Run the check above, then force-push `local`.

To change one of our commits, change its branch, then cherry-pick the new commit into `local` in place of the old one. To update an upstream pull request, fetch its head (`git fetch origin pull/<n>/head`) and replace the squash with a new one: `git diff $(git merge-base origin/main FETCH_HEAD) FETCH_HEAD | git apply --3way`. A pull request that needed real conflict work against `main` lives as a branch `pr/<n>-<topic>` on the fork instead (one squash commit on `main`, authored by the PR's author): rebase that branch onto `main`, or redo the squash there when the PR moves, and cherry-pick it into `local`. Drop the squash when upstream merges the pull request and the new base tag includes it.
